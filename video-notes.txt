4.SystemRescueCD
 SystemRescueCd (now called SystemRescue) is a Linux-based bootable live CD, DVD, or USB stick designed specifically for system rescue and recovery tasks.
 What is it used for?
SystemRescue is mainly used to:
Repair unbootable systems (e.g., fix broken bootloaders like GRUB)
Recover lost data (from corrupted or deleted partitions)
Back up and restore data (using tools like dd, partimage, rsync, etc.)
Diagnose hardware problems
Edit partitions (with tools like GParted or parted)
Reset forgotten passwords

Access Linux and Windows file systems when the OS won't boot
     What tools does it include?

Some popular tools included:
fsck, ntfsfix — file system repair
testdisk, photorec — recover lost partitions or files
gparted — graphical partition editor
ddrescue — advanced data recovery from failing disks
grub tools — repair or reinstall GRUB bootloader
chroot — enter a broken system’s environment to repair it
Networking tools — SSH, ping, traceroute, etc.

5.Vagrant- A tool which allows us to build a virtual environment.
Vagrant is an open-source tool for building and managing virtualized development environments.

It was created by HashiCorp and is mainly used to create reproducible and portable development setups, usually using VirtualBox or other providers (like VMware, Hyper-V, Docker).
 Why do we use Vagrant?
Consistency: Every developer can have the same environment (same OS, same dependencies), which reduces "it works on my machine" problems.

13.Filesystem Hierarchy Standard

It gives a overview about a unix filesystem should look like.
By understanding it, it will helps us predict the various locations of files and directories.

Root Directory /
The top of the filesystem tree. Everything starts here.

Essential Directories under /
Directory	Purpose
/bin	Essential user binaries (programs) needed for booting and single-user mode, e.g., ls, cp, mv, cat, bash.
/sbin	Essential system binaries for system administration, e.g., fsck, mount, shutdown.
/boot	Boot loader files, Linux kernel, initrd images, and GRUB/LILO configs.
/dev	Device files (special files that represent hardware), e.g., /dev/sda, /dev/null, /dev/tty.
/etc	Host-specific configuration files, e.g., /etc/passwd, /etc/hosts, /etc/fstab.
/home	Home directories of users (except root), e.g., /home/alice.
/lib	Shared libraries needed for programs in /bin and /sbin.
/media	Mount point for removable media like USB drives, CDs.
/mnt	Temporary mount point for filesystems (admin use).
/opt	Optional add-on software packages.
/root	Home directory for the root user.
/run	Runtime variable data (process IDs, sockets, runtime configs).
/srv	Data for services provided by the system (e.g., web, FTP).
/tmp	Temporary files (cleared on reboot in many distros).

/usr	Secondary hierarchy (user programs and data):
├── /usr/bin – Non-essential user binaries (e.g., gcc, python, firefox).	
├── /usr/sbin – Non-essential system binaries.	
├── /usr/lib – Libraries for /usr/bin and /usr/sbin.	
├── /usr/local – Locally installed software (overrides system packages).

/var	Variable data files: logs, caches, mail, spool, lock files.
├── /var/log – Log files.	
├── /var/tmp – Temporary files preserved between reboots.	
├── /var/spool – Queued tasks (printing, mail).

16. symbolic link and hard link

symbolic link - access a pointer to a real file that points to the data on a file.
hard link - we give the existing file a second name and this second name points to the data .

ln - makes links between files. it makes hard links by default but if we want to create symbolic link we have to use ln --symbolic or we can use ln -s.

these files have inode (inode has metadata of the file) which consists of size,type,device,uid/gid,mode(permissions),timestamps,link count, pointers to the disk blocks.

hard link files will have the same inode number as of original file whereas symbolic link will have a different inode.



Conclusion

Symbolic links				| Hard links
Easy to understand			|hard to recognize
works for files and directories		|only works for files
works across filesystems		|not across filesystems
					|Better performance
